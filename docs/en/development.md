# Development Guide

This document introduces how to set up the development environment, debug code, and extend nanocode's functionality.

## Development Environment Setup

### Prerequisites

- Node.js >= 18
- TypeScript 5.7+
- Anthropic API Key

### Installation Steps

```bash
# 1. Clone project
git clone <repo-url>
cd nano-ts

# 2. Install dependencies
npm install

# 3. Configure environment variables
cp .env.example .env
# Edit .env, add ANTHROPIC_API_KEY

# 4. Type checking
npm run check

# 5. Run
npm start
```

## Project Scripts

| Command | Description |
|---------|-------------|
| `npm start` | Start program |

### Integrating Other Models

Modify `callApi` function to support multiple models:

```typescript
async function callApi(messages: Message[], model?: string): Promise<...> {
  if (model?.startsWith("openai:")) {
    // Call OpenAI API
    return callOpenAI(messages, model.replace("openai:", ""));
  }
  // Default Anthropic
  return client.messages.create({...});
}
```

## Code Standards

### Naming Conventions

- **Files**: Lowercase, hyphen-connected (e.g., `my-util.ts`)
- **Types**: PascalCase (e.g., `ToolConfig`, `ReadParams`)
- **Functions**: camelCase (e.g., `runTool`, `safeGetMtime`)
- **Constants**: UPPER_SNAKE_CASE (e.g., `TOOLS`, `SYSTEM_PROMPT`)

### Import Order

```typescript
// 1. Node.js built-in
import { readFileSync } from "node:fs";

// 2. Third-party libraries
import { z } from "zod";
import Anthropic from "@anthropic-ai/sdk";

// 3. Local modules
import { ReadSchema } from "./types.js";
import { safeGetMtime } from "./utils.js";
```

### Type Safety Best Practices

1. **Avoid any**
   ```typescript
   // Avoid
   function foo(x: any) { }

   // Recommended
   function foo(x: unknown) { }
   ```

2. **Use concrete types**
   ```typescript
   // Avoid
   function read(args: Record<string, unknown>)

   // Recommended
   function read(args: ReadParams)
   ```

3. **Make full use of Zod**
   ```typescript
   // Schema definition
   const Schema = z.object({ name: z.string() });

   // Type inference
   type Params = z.infer<typeof Schema>;

   // Runtime validation
   const parsed = Schema.parse(unknownData);
   ```

## Common Issues

### Q: Tool call returns "validation error"

LLM passed parameters that don't match Zod Schema. Check:
- Is the Schema definition correct?
- Is `.describe()` clear?
- Are required fields marked as `.optional()`?

### Q: API returns 400 error

May be a tool schema format issue:
- Check format generated by `makeSchema()`
- Ensure `input_schema.type` is `"object"`
- Verify `properties` is not empty

### Q: Program won't start

Check:
- Is `ANTHROPIC_API_KEY` set?
- Node.js version >= 18?
- Did you run `npm install`?

### Q: Type checking fails

Run `npm run check` to see errors:
- Check if import paths are correct (need `.js` suffix)
- Ensure tsx is installed
- Check TypeScript version

## Performance Optimization

### 1. Large File Handling

read tool supports pagination:
```typescript
{ path: "./large.log", offset: 0, limit: 100 }
```

### 2. Reduce API Calls

- Combine related operations into a single tool
- Use glob + grep combination instead of multiple calls

### 3. Message History Compression

Can summarize after long conversations:
```typescript
// When messages get too long
if (messages.length > 50) {
  const summary = await generateSummary(messages);
  messages = [systemMessage, { role: "user", content: summary }];
}
```
